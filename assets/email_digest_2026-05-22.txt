1. **面向 LLM Agent 的运行时编排与轨迹优化** — 围绕 Agent 系统的运行时编排、轨迹压缩与推理时对齐，探讨如何通过事件溯源、轨迹编译和推理时规划提升 Agent 在复杂任务中的效率与可审计性。

## 三篇论文方向与六个创新点

### 论文方向一：面向 LLM Agent 的运行时编排与轨迹优化

**拟定论文题目：** 基于事件溯源与轨迹编译的 LLM Agent 运行时编排与可审计性增强方法

**论文核心问题：** 如何通过重新设计 Agent 运行时架构（从以模型为中心转向以日志为中心），并结合轨迹编译与推理时对齐，提升 Agent 在复杂任务中的执行效率、可审计性与可复现性。

#### 创新点一：事件溯源驱动的 Agent 运行时架构创新

大多数现有方法将 LLM 对话循环作为 Agent 框架的核心，工具调用、规则和日志层作为附加组件，导致状态持久化依赖检索-摘要式记忆系统，难以实现确定性重放和端到端溯源 [2](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-05-22&paperId=2605.21997)[6](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-05-22&paperId=2605.22166)[12](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-05-22&paperId=2605.22608)。少数现有方法开始关注运行时日志的审计价值，但通常将日志视为事后观察工具，而非运行时状态的真实来源，且缺乏对 Agent 执行轨迹的轻量级分支与复现支持 [13](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-05-22&paperId=2605.22634)[17](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-05-22&paperId=2605.22535)[25](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-05-22&paperId=2605.21516)。为此，本文提出基于事件溯源的 Agent 运行时架构，以仅追加事件日志作为唯一真实来源，将工作图定义为日志的确定性投影，所有行为（函数、类、LLM 例程）通过响应图变化并发射新事件实现协调，从而提供确定性重放、低成本分支和端到端血缘追踪能力 [2](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-05-22&paperId=2605.21997)[29](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-05-22&paperId=2605.22154)。

**创新类型：** 系统框架创新

**创新性判断：** 该创新点从架构层面颠覆了现有 Agent 框架以模型为中心的设计范式，转向以日志为中心，解决了可审计性、可复现性和可分支性三个核心问题。文献池中 [2](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-05-22&paperId=2605.21997) 直接支持该架构的核心思想，[6](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-05-22&paperId=2605.22166)[13](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-05-22&paperId=2605.22634)[17](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-05-22&paperId=2605.22535)[25](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-05-22&paperId=2605.21516) 从不同角度佐证了现有方法的局限。

#### 创新点二：轨迹编译与推理时对齐的联合优化创新

大多数现有方法将 Agent 工作流作为外部编排器在 LLM 之上运行，每轮注入指令和路由决策，消耗上下文窗口且依赖前沿模型，暴露专有流程 [20](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-05-22&paperId=2605.22502)[25](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-05-22&paperId=2605.21516)[28](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-05-22&paperId=2605.22642)。少数现有方法尝试将工作流编译到模型权重中（如 SimpleTOD、FireAct），但开发者采纳仍以编排为主，且现有编译方法缺乏对推理时轨迹对齐的显式优化 [3](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-05-22&paperId=2605.21996)[7](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-05-22&paperId=2605.21850)[20](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-05-22&paperId=2605.22502)。为此，本文提出轨迹编译与推理时对齐的联合优化方法，将 Agent 工作流编译为轻量级微调模型的权重（地下 Agent），同时在推理时通过任务分解和引导执行机制对齐轨迹，以在降低推理成本的同时保持任务成功率 [20](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-05-22&paperId=2605.22502)[25](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-05-22&paperId=2605.21516)[29](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-05-22&paperId=2605.22154)。

**创新类型：** 方法设计创新 + 性能优化创新

**创新性判断：** 该创新点将轨迹编译（降低推理成本）与推理时对齐（保持任务成功率）两个目标联合优化，解决了现有方法中二者分离导致的效率-质量权衡问题。文献池中 [20](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-05-22&paperId=2605.22502) 直接支持轨迹编译的有效性，[25](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-05-22&paperId=2605.21516) 和 [29](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-05-22&paperId=2605.22154) 支持推理时对齐的必要性。

### 论文方向二：面向 LLM 推理与训练的弹性资源配置与并行调度

**拟定论文题目：** 面向大模型推理与训练的弹性资源配置与设备内并行调度联合优化方法

**论文核心问题：** 如何在 LLM 推理与训练场景中，通过实时重配置、设备内并行调度和跨区域 Spot 实例智能部署，降低资源成本并提升利用率。

#### 创新点三：实时重配置与弹性训练运行时创新

大多数现有方法将弹性训练的重配置视为停止-重启过程，通过检查点外部化分布式状态、在新拓扑上重建运行时并重启训练，导致每次调整都带来存储密集型恢复和大量停机时间 [9](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-05-22&paperId=2605.22014)[16](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-05-22&paperId=2605.22778)[23](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-05-22&paperId=2605.22331)。少数现有方法开始探索实时重配置技术，但通常局限于特定并行策略或需要侵入式代码修改，难以适应混合并行训练世界的动态切换 [9](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-05-22&paperId=2605.22014)[24](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-05-22&paperId=2605.21603)[30](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-05-22&paperId=2605.22239)。为此，本文提出实时重配置的弹性训练运行时，在当前训练世界继续运行的同时异步准备目标世界，在隔离环境中引导新加入的工作节点，通过有界内存交接实现混合并行训练世界之间的无缝切换，以消除检查点 I/O 和进程重启带来的停机时间 [9](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-05-22&paperId=2605.22014)[24](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-05-22&paperId=2605.21603)。

**创新类型：** 系统框架创新 + 性能优化创新

**创新性判断：** 该创新点针对弹性训练中重配置开销大的核心问题，提出实时交接而非停止-重启的方案。文献池中 [9](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-05-22&paperId=2605.22014) 直接支持该架构，[24](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-05-22&paperId=2605.21603) 支持设备内并行调度的灵活性需求，[16](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-05-22&paperId=2605.22778) 和 [23](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-05-22&paperId=2605.22331) 从不同角度佐证了现有弹性部署方案的局限。

#### 创新点四：可编程算子调度与设备内并行策略创新

大多数现有方法采用静态、顺序的编程模型执行 ML 推理和训练，导致算子执行时资源利用率不足，且集成设备内并行策略需要侵入式、模型特定的代码重构 [24](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-05-22&paperId=2605.21603)[9](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-05-22&paperId=2605.22014)[22](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-05-22&paperId=2605.22188)。少数现有方法开始探索设备内并行调度，但策略对执行上下文（工作负载、模型架构、硬件）高度敏感，开发者需要实现和维护多个专用解决方案，缺乏透明且灵活的集成方式 [24](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-05-22&paperId=2605.21603)[15](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-05-22&paperId=2605.22337)[22](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-05-22&paperId=2605.22188)。为此，本文提出可编程算子调度框架，通过解耦逻辑模型定义与物理执行调度，提供图分区注解和可编程接口，允许开发者定义自定义设备内并行策略，同时后端自动管理算子调度与资源分配，以透明地提升资源利用率并降低工程成本 [24](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-05-22&paperId=2605.21603)[15](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-05-22&paperId=2605.22337)[22](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-05-22&paperId=2605.22188)。

### 论文方向三：面向 LLM 后训练与微调的稳定性与多样性增强

**拟定论文题目：** 面向 LLM 后训练与微调的稳定性恢复与多样性增强联合优化方法

**论文核心问题：** 如何解决 LLM 后训练（如 RLVR）中的训练不稳定问题，以及微调中的多概念生成干扰和推理时搜索多样性不足问题。

#### 创新点五：基于裁剪边界恢复的 RLVR 训练稳定性创新

大多数现有方法在 RLVR 训练中使用硬裁剪规则，将超出裁剪阈值的 tokens 直接丢弃，导致近边界区域的信息性信号被浪费，造成训练不稳定和次优收敛 [14](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-05-22&paperId=2605.22703)[10](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-05-22&paperId=2605.22817)[28](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-05-22&paperId=2605.22642)。少数现有方法尝试通过软裁剪或自适应阈值缓解此问题，但通常引入额外超参数或改变优化目标，难以作为即插即用模块集成到现有 GRPO 风格框架中 [14](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-05-22&paperId=2605.22703)[21](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-05-22&paperId=2605.22177)[25](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-05-22&paperId=2605.21516)。为此，本文提出近边界随机恢复（NSR）方法，通过随机保留略超出裁剪边界的 tokens 来恢复丢失信号，作为最小化的即插即用修改，在期望中引入隐式梯度衰减以稳定训练 [14](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-05-22&paperId=2605.22703)[10](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-05-22&paperId=2605.22817)[21](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-05-22&paperId=2605.22177)。

**创新类型：** 方法设计创新

**创新性判断：** 该创新点精准定位了 RLVR 训练中硬裁剪导致的信息丢失瓶颈，并提出极简的随机恢复方案。文献池中 [14](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-05-22&paperId=2605.22703) 直接支持该方法的有效性，[10](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-05-22&paperId=2605.22817) 和 [28](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-05-22&paperId=2605.22642) 从不同角度佐证了 RLVR 训练的挑战。

#### 创新点六：双层级正交适应与向量策略优化的多样性增强创新

大多数现有方法在 LLM 后训练中优化预定义的标量奖励，导致策略产生低熵响应分布，难以在推理时搜索中展现所需多样性 [10](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-05-22&paperId=2605.22817)[1](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-05-22&paperId=2605.22743)[28](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-05-22&paperId=2605.22642)。少数现有方法开始关注多样性训练，但通常采用后处理融合或冻结适应子空间，限制了表达能力和概念保真度，且缺乏对多目标奖励空间的显式建模 [1](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-05-22&paperId=2605.22743)[10](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-05-22&paperId=2605.22817)[21](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-05-22&paperId=2605.22177)。为此，本文提出双层级正交适应与向量策略优化联合方法，在参数高效微调层面通过双层优化联合学习 LoRA 基以最小化残差干扰能量，在策略优化层面通过向量奖励估计器训练策略产生多样化解决方案，以在保持概念保真度的同时提升推理时搜索的多样性 [1](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-05-22&paperId=2605.22743)[10](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-05-22&paperId=2605.22817)[21](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-05-22&paperId=2605.22177)。

**创新类型：** 方法设计创新 + 问题建模创新

创新点五解决“RLVR 训练如何稳定”的问题，创新点六解决“微调与策略优化如何增强多样性”的问题。二者属于同一篇论文主题（LLM 后训练与微调的稳定性与多样性增强），但分别对应训练稳定性和输出多样性两个不同技术层面，且可以联合部署（先稳定训练，再增强多样性），不存在重复。

**建议实验设计：**

- **对比方法：** 标准 GRPO、硬裁剪 RLVR、标量奖励优化、现有 LoRA 变体、后处理融合方法
- **实验数据或场景：** 多概念图像生成 [1](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-05-22&paperId=2605.22743)、代码生成 [10](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-05-22&paperId=2605.22817)、电子表格任务 [28](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-05-22&paperId=2605.22642)、推理基准
- **评价指标：** 训练收敛速度、训练稳定性（损失方差）、概念保真度、生成多样性（熵、独特解数量）、推理时搜索成功率
- **消融实验：** NSR vs. 硬裁剪、正交适应 vs. 标准 LoRA、向量策略 vs. 标量策略、联合训练 vs. 分阶段训练
