## 论文方向一：大模型推理服务中的资源解耦与高效缓存管理

**拟定论文题目：** 面向稀疏注意力模型与长上下文场景的 CXL 驱动 KV 缓存按需取回与 4-bit 量化部署优化

**论文核心问题：** 如何利用新型互连技术（CXL）实现 KV 缓存的细粒度按需取回，并结合 4-bit 量化压缩，在上下文密集型 Agent 负载下同时降低推理时延与显存占用。

### 创新点一：CXL 驱动的稀疏注意力 KV 缓存按需取回机制

大多数现有方法依赖 RDMA 的粗粒度预取策略，在解码前将完整前缀 KV 缓存从远端拉取到本地显存，导致传输瓶颈与本地显存浪费 [1, 21, 26]。少数现有方法开始探索基于新型互连的细粒度取回，但尚未针对稀疏注意力模型中仅少数 KV 条目活跃的特性进行优化，取回粒度仍偏大 [1, 21]。为此，本文提出基于 CXL 缓存行粒度加载/存储语义的按需取回机制，在推理过程中仅取回当前解码步骤所需的 top-k KV 条目，以消除冗余传输并降低首 Token 时延（TTFT）。

- **创新类型：** 系统架构创新 + 方法设计创新
- **创新性判断：** 池内文献 [1](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-21&paperId=2606.19746) 直接提出了 SAC 系统，利用 CXL 实现稀疏注意力模型的 KV 缓存按需取回，本文创新点一与 [1](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-21&paperId=2606.19746) 的核心贡献高度重合。**该创新点已被池内文献完整覆盖，不建议作为正式创新点输出。**

### 创新点二：面向上下文密集型 Agent 负载的 4-bit KV 缓存量化与部署优化

大多数现有 KV 缓存量化方法主要针对单轮长上下文推理场景，未考虑多轮 Agent 工作负载中前缀复用、短轮次高并发对缓存驻留时间与服务吞吐量的联合影响 [2, 16, 26]。少数现有方法开始探索 4-bit 量化在 Agent 场景下的部署，但通常采用对称量化或固定格式，在非对称 K/V 分布下量化精度损失较大，且缺乏针对特定硬件（如 AMD CDNA4）的原生 FP4 支持 [2, 22]。为此，本文提出面向多轮 Agent 工作负载的 4-bit KV 缓存量化方案，采用非对称 K/V 处理、Walsh-Hadamard 旋转与块缩放变体，并设计基于 FP8 查询与 FP4 KV 张量的原生 scaled-MFMA 解码注意力核，以在保证任务质量的前提下最大化缓存压缩比与服务吞吐量。

- **创新类型：** 方法设计创新 + 部署优化创新
- **创新性判断：** 池内文献 [2](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-21&paperId=2606.20474) 提出了 UltraQuant，专门针对上下文密集型 Agent 负载设计了 4-bit KV 缓存量化方案，包括非对称 K/V 处理、Walsh-Hadamard 旋转、FP4 近似路径及 AMD GPU 优化。**该创新点已被池内文献完整覆盖，不建议作为正式创新点输出。**

**该论文两个创新点之间的关系：** 创新点一解决“如何按需取回 KV 缓存”，创新点二解决“如何压缩驻留 KV 缓存”。二者属于同一论文主题（大模型推理缓存管理），但分别对应取回策略与压缩策略，不存在重复。**然而，两个创新点均已被池内文献完整覆盖，该论文方向整体创新性不足。**

**建议实验设计：**
- 对比方法：SAC [1](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-21&paperId=2606.19746)、UltraQuant [2](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-21&paperId=2606.20474)、vLLM FP8 基线、传统 RDMA 预取
- 实验数据或场景：DeepSeek-V3.2 模型 + 多轮 Agent 工作负载（如 UltraQuant 中的 long-context multi-turn agentic workload）
- 评价指标：吞吐量、TTFT、TBT、缓存命中率、量化精度损失
- 消融实验：CXL 按需取回 vs. 全量预取、4-bit 非对称量化 vs. 对称量化、FP4 原生核 vs. 模拟核

## 论文方向二：多 Agent 系统的运行时状态管理与编排效率

**拟定论文题目：** 面向多 Agent 协作的会话中心运行时抽象与拓扑感知并行编排方法

**论文核心问题：** 如何解决多 Agent 协作中状态碎片化、并发冲突与编排开销问题，通过统一的运行时抽象与高效的并行调度机制提升系统吞吐与可靠性。

### 创新点三：会话中心运行时状态抽象与分支-合并机制

大多数现有多 Agent 系统将对话记录、工具调用结果、内存事件、工作空间位置等运行时状态分散存储在不同组件中，导致状态碎片化，难以进行统一的检查、回放与调试 [3, 11, 14]。少数现有方法开始引入中心化的运行时抽象，但通常将状态视为不可变的日志序列，缺乏对分支、合并与回放的原生支持，难以应对并发 Agent 间的状态冲突 [11, 14]。为此，本文提出以 Session 为核心的一等运行时抽象，将对话片段、沙箱位置、血缘元数据、Token 用量与待办工作统一封装为可分支、可检查、可回放、可组合的运行时值，使 fork、merge 与 replay 成为显式的运行时操作而非从外部痕迹重建的状态。

- **创新类型：** 系统框架创新 + 问题建模创新
- **创新性判断：** 池内文献 [11](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-21&paperId=2606.19409) 提出了 OpenRath，其核心贡献正是以 Session 为中心的一等运行时抽象，支持分支、检查、回放与组合。**该创新点已被池内文献完整覆盖，不建议作为正式创新点输出。**

### 创新点四：拓扑感知的并行编排与事件驱动任务管理

大多数现有多 Agent 编排方法采用顺序执行或简单的 DAG 调度，在 Agent 数量增加时，由于未充分利用任务间的依赖无关性，端到端延迟随规模线性增长 [4, 7, 14]。少数现有方法引入并行工作流或拓扑执行，但在企业级规模（200+ Agent）下，Agent 发现噪声成为主要瓶颈，简单任务的性能退化比复杂任务更严重 [4, 7]。为此，本文提出拓扑感知的并行编排框架，通过动态识别独立任务实现依赖感知的并发执行，并引入事件驱动的任务管理器，利用优先级推理、相关事件合并与抢占机制，在保持结构正确性与安全性的同时，将高优先级队列延迟降低 40% 以上。

- **创新类型：** 方法设计创新 + 系统框架创新
- **创新性判断：** 池内文献 [4](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-21&paperId=2606.19382) 提出了 DynAMO，采用 Plan-then-Execute 架构生成可验证的工作流图，支持 SequentialWorkflow 与 ParallelWorkflow，并通过动态识别独立任务提升并行效率。池内文献 [7](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-21&paperId=2606.20058) 提出了事件驱动的 Task Manager，包含优先级推理、相关事件合并与抢占机制。**该创新点已被池内文献 [4](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-21&paperId=2606.19382) 和 [7](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-21&paperId=2606.20058) 完整覆盖，不建议作为正式创新点输出。**

**该论文两个创新点之间的关系：** 创新点三解决“运行时状态如何统一表示”，创新点四解决“Agent 任务如何高效并行编排”。二者属于同一论文主题（多 Agent 系统运行时管理），但分别关注状态抽象与调度编排，不存在重复。**然而，两个创新点均已被池内文献完整覆盖，该论文方向整体创新性不足。**

**建议实验设计：**
- 对比方法：OpenRath [11](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-21&paperId=2606.19409)、DynAMO [4](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-21&paperId=2606.19382)、DAG Plan and Execute [7](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-21&paperId=2606.20058)、ReAct [7](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-21&paperId=2606.20058)
- 实验数据或场景：多 Agent 协作基准（如 AssetOpsBench [4](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-21&paperId=2606.19382)）+ 企业级规模场景（Persona/Department/Enterprise [7](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-21&paperId=2606.20058)）
- 评价指标：端到端延迟、并发加速比、状态回放成功率、高优先级队列延迟
- 消融实验：Session 抽象 vs. 无状态基线、拓扑感知并行 vs. 顺序执行、事件驱动 vs. 轮询调度

## 论文方向三：LLM 推理与微调中的成本-质量权衡与自适应控制

**拟定论文题目：** SLA 约束下成本最优的 LLM 请求路由与预算感知推理验证分配方法

**论文核心问题：** 如何在满足用户满意度 SLA 的前提下，通过在线学习与自适应控制，最小化 LLM 推理服务的运营成本，并解决稀疏反馈与预算约束下的验证分配问题。

### 创新点五：基于稀疏用户反馈的 SLA 约束成本最优路由

大多数现有 LLM 请求路由方法依赖完整的质量反馈信号或离线训练数据，在真实生产环境中难以获取，且缺乏严格的 SLA 合规保证 [8, 26]。少数现有方法开始探索在线学习与稀疏反馈下的路由策略，但通常需要针对每个工作负载进行大量调参，且无法提供理论上的成本最优性与 SLA 合规保证 [8](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-21&paperId=2606.19376)。为此，本文提出 SLARouter，一种在线路由算法，从生产系统中可获取的稀疏、单侧用户反馈中学习成本最优策略，同时提供成本最优性与严格 SLA 合规的理论保证，无需针对每个基准进行调参即可将运营成本降低至现有方法的 2.2 倍以下。

- **创新类型：** 方法设计创新 + 理论保证创新
- **创新性判断：** 池内文献 [8](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-21&paperId=2606.19376) 提出了 SLARouter，其核心贡献正是基于稀疏用户反馈的在线路由算法，提供成本最优性与 SLA 合规的理论保证。**该创新点已被池内文献完整覆盖，不建议作为正式创新点输出。**

### 创新点六：预算感知的选择性推理验证分配

大多数现有推理时验证方法对所有请求或所有推理步骤进行统一验证，导致计算资源浪费在已经正确的答案上，甚至引入有害的答案变更 [9, 25]。少数现有方法开始探索选择性验证，但通常需要训练独立的验证器或依赖复杂的元认知模型，部署成本高且难以在服务层直接集成 [9, 25]。为此，本文提出 Selective Verification for Reasoning Allocation (SevRA)，一种服务层控制器，利用服务可见的尝试状态（如中间步骤的置信度、重试次数）训练可恢复性感知门控，决定是否对冻结求解器的初始答案进行主动验证，在保持准确率的同时将后生成 Token 减少 26.8%，有害翻转从 2.2% 降至 1.0%。

- **创新类型：** 方法设计创新 + 系统框架创新
- **创新性判断：** 池内文献 [25](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-21&paperId=2606.19808) 提出了 SevRA，其核心贡献正是基于服务可见尝试状态的选择性验证分配，无需训练独立验证器。**该创新点已被池内文献完整覆盖，不建议作为正式创新点输出。**
