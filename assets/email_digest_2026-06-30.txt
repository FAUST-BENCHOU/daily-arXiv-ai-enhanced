## 三篇论文方向与六个创新点

### 论文方向一：面向 LLM 推理服务的能效感知调度与资源弹性管理

**拟定论文题目：** 面向共享 GPU 环境的能效感知 LLM 推理调度与弹性资源管理方法

**论文核心问题：** 如何在共享 GPU 集群中，通过联合调度、分区与核心-注意力解耦，在满足服务等级目标的前提下最小化集群能耗并实现弹性扩展。

#### 创新点一：能效感知的请求放置与 GPU 分区联合调度

大多数现有方法将 LLM 推理调度聚焦于吞吐量或尾部时延优化，在共享 GPU 场景下采用全局-局部两级调度器，但未将能耗作为首要优化目标，导致集群能效低下 [1](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-30&paperId=2606.30391)[3](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-30&paperId=2606.30560)[13](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-30&paperId=2606.29708)。少数现有方法开始关注 GPU 分区（如 MIG）与能耗优化，但通常将请求放置、SM 分区与 GPU 工作点选择作为独立决策，缺乏联合优化框架，难以在动态负载下同时满足 TTFT/TBT 时延约束 [11](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-30&paperId=2606.29775)[28](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-30&paperId=2606.30533)。为此，本文提出一种能效感知的联合调度方法，将请求放置、SM 分区和 GPU 工作点选择纳入统一优化模型，在 SLO 约束下最小化集群能耗。

**创新类型：** 问题建模创新 + 方法设计创新

**创新性判断：** 文献池中 Festina [1](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-30&paperId=2606.30391) 提出了能效优先的调度平面，但侧重于全局调度器层面的请求放置；SMART-MIG [11](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-30&paperId=2606.29775) 关注 MIG 分区与作业调度，但未将能耗与分区决策联合建模。本文的创新在于将请求放置、SM 分区和 GPU 工作点选择三者联合优化，填补了现有方法在能效感知联合调度方面的空白。

#### 创新点二：核心-注意力解耦的弹性解码架构

大多数现有 LLM 推理系统在解码阶段将投影/FFN 计算与注意力计算紧密耦合，当突发长上下文请求超出部署容量时，只能通过启动完整模型副本进行实例级扩展，导致启动延迟、内存开销和批处理碎片化 [3](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-30&paperId=2606.30560)[12](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-30&paperId=2606.29207)[13](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-30&paperId=2606.29708)。少数现有方法尝试将注意力计算与权重计算分离，但缺乏弹性路由机制，无法在 token 粒度上动态调整注意力节点规模 [1](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-30&paperId=2606.30391)[11](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-30&paperId=2606.29775)。为此，本文提出一种核心-注意力解耦的弹性解码架构，将稳定的投影/FFN 路径与可弹性扩展的注意力计算路径分离，通过 token 范围路由表和 UCX 端点通信实现注意力节点的按需扩展。

**创新类型：** 系统框架创新 + 在线反馈机制创新

**创新性判断：** KernelFlume [12](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-30&paperId=2606.29207) 提出了核心-注意力解耦架构，但本文的创新在于将这种解耦架构与能效感知调度（创新点一）相结合，形成闭环的弹性资源管理系统。文献池中尚无工作将解耦架构与能效调度联合设计。

### 论文方向二：面向长上下文与动态负载的 KV 缓存压缩与推理加速

**拟定论文题目：** 面向长上下文推理的无阈值 KV 缓存压缩与覆盖驱动驱逐方法

**论文核心问题：** 如何在长上下文 LLM 推理中，在不依赖输入特定阈值的前提下实现无损 KV 缓存压缩，并通过覆盖驱动策略提升缓存效率。

#### 创新点三：无阈值的自适应 KV 缓存预算分配

大多数现有 KV 缓存压缩方法依赖输入/领域特定的阈值来预先确定缓存预算，在开放域输入（涵盖不同领域、长度和难度）上性能退化严重，因为阈值选择缺乏明确边界 [8](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-30&paperId=2502.16886)[17](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-30&paperId=2606.29563)。少数现有方法尝试自适应调整预算分配，但仍需预设全局阈值或依赖注意力分布统计量，难以在无损压缩和通用性之间取得平衡 [3](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-30&paperId=2606.30560)[6](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-30&paperId=2606.29223)。为此，本文提出一种无阈值的 KV 缓存压缩方法，通过自适应预算分配机制，在不依赖预定义阈值的情况下动态调整每个 token 的缓存优先级，以保持与完整缓存相当的性能。

**创新类型：** 问题建模创新 + 方法设计创新

**创新性判断：** ReFreeKV [8](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-30&paperId=2502.16886) 首次提出“无阈值”目标，但本文的创新在于将无阈值压缩与覆盖驱动驱逐策略（创新点四）相结合，形成完整的缓存管理方案。文献池中尚无工作将无阈值预算分配与覆盖驱动策略联合设计。

#### 创新点四：覆盖驱动的 KV 缓存驱逐策略

大多数现有 KV 缓存驱逐策略利用注意力稀疏性选择性地存储 token 子集，但未考虑驱逐后 token 覆盖率的降低，导致长上下文推理任务性能显著下降 [8](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-30&paperId=2502.16886)[17](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-30&paperId=2606.29563)。少数现有方法开始关注 token 覆盖率与互信息的关系，但缺乏理论证明和可实现的驱逐算法，难以在实际部署中保证预测准确性 [3](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-30&paperId=2606.30560)[6](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-30&paperId=2606.29223)。为此，本文提出一种覆盖驱动的 KV 缓存驱逐策略，通过最大化缓存中唯一 token 的覆盖率来保持输入-输出互信息，并设计高效的驱逐算法，在降低内存占用的同时维持推理性能。

**创新类型：** 性能预测创新 + 优化求解创新

**创新性判断：** K-VEC [17](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-30&paperId=2606.29563) 提出了覆盖率驱动的驱逐思想，但本文的创新在于将覆盖率最大化与无阈值预算分配（创新点三）相结合，并给出互信息损失的严格理论分析。文献池中尚无工作将覆盖驱动策略与无阈值机制联合设计。

### 论文方向三：面向预算约束与多跳推理的自适应检索增强生成

**拟定论文题目：** 面向固定预算的多跳推理自适应检索增强生成方法

**论文核心问题：** 如何在固定检索预算下，通过置信度估计、诊断-修复框架和图结构检索提升 RAG 系统在多跳推理任务中的可靠性与效率。

#### 创新点五：预算感知的自适应检索停止与置信度估计

大多数现有 RAG 系统为每个问题检索固定数量的文档，无论问题难度如何，导致简单问题浪费计算资源，困难问题检索不足，且无法提供答案可信度信号 [2](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-30&paperId=2606.28737)[27](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-30&paperId=2606.29090)。少数现有方法引入自适应检索策略，但通常需要重新训练底层模型或依赖内部模型信号，在商业 API 等黑盒场景下实用性有限 [9](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-30&paperId=2606.29377)[30](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-30&paperId=2606.30093)。为此，本文提出一种训练无关、骨干无关的自适应检索框架，通过组合模型自身置信度、答案-证据一致性和证据方差三个信号进行置信度估计，在固定检索预算下自适应决定是否停止或继续检索。

**创新类型：** 指标体系创新 + 评价方法创新

**创新性判断：** AB-RAG [27](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-30&paperId=2606.29090) 提出了训练无关的自适应检索框架，但本文的创新在于将自适应检索与诊断-修复框架（创新点六）相结合，形成完整的预算约束 RAG 系统。文献池中尚无工作将自适应预算分配与诊断-修复机制联合设计。

#### 创新点六：诊断-修复驱动的多跳推理错误纠正

大多数现有 RAG 系统在多跳推理中面临证据缺失、弱相关或生成不忠实于检索上下文的问题，且缺乏可解释的失败诊断机制 [2](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-30&paperId=2606.28737)[27](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-30&paperId=2606.29090)。少数现有方法引入诊断-修复框架，但通常依赖微调、内部模型信号或资源不敏感的升级策略，在黑盒和预算受限场景下实用性有限 [9](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-30&paperId=2606.29377)[30](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-30&paperId=2606.30093)。为此，本文提出一种模型无关、资源感知的诊断-修复框架，从查询、检索证据和生成响应中提取可解释的失败签名，并在显式时延和显存约束下选择纠正动作，以提升多跳推理的可靠性。

**创新类型：** 方法设计创新 + 约束处理创新

**创新性判断：** D2R-RAG [9](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-30&paperId=2606.29377) 提出了诊断-修复框架，但本文的创新在于将诊断-修复与自适应检索（创新点五）相结合，形成预算约束下的完整 RAG 系统。文献池中尚无工作将自适应预算分配与诊断-修复机制联合设计。
