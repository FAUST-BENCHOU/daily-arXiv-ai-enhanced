## 论文方向一：大语言模型推理加速与视觉/扩散/缓存压缩

**拟定论文题目：** 面向多模态与扩散架构的训练无关推理加速：从视觉 Token 剪枝到动态缓存与并行解码的统一框架

**论文核心问题：** 如何在不引入额外训练开销的前提下，针对多模态大语言模型（MLLM）和扩散语言模型（dLLM）的推理瓶颈，设计模型无关的加速方法，同时兼顾视觉 Token 冗余、KV Cache 动态分配与并行解码策略。

### 创新点一：信息论驱动的视觉 Token 剪枝与扩散模型动态缓存协同优化

大多数现有方法在处理 MLLM 的视觉 Token 冗余时，要么依赖注意力分数保留高注意力 Token，要么基于多样性准则保留代表性 Token，但前者容易保留冗余 Token，后者则对用户指令不敏感，且两者均缺乏对剪枝目标的原理性建模 [1](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-26&paperId=2606.27161)[16](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-26&paperId=2606.26769)[17](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-26&paperId=2606.26120)。少数现有方法尝试结合多种准则或引入缓存-预测机制来加速扩散模型，但扩散模型中的离散外推操作与连续扩散轨迹存在错位，导致高加速比下质量严重下降，且静态缓存策略无法适应 Token 属性在层间和解码步间的动态变化 [16](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-26&paperId=2606.26769)[17](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-26&paperId=2606.26120)。为此，本文提出一种信息论驱动的协同加速框架，在 MLLM 端基于 Token 最优保留集构建原则（任务相关性、信息覆盖、语义多样性）进行训练无关的视觉 Token 剪枝 [1](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-26&paperId=2606.27161)，同时在扩散语言模型端引入动态缓存更新机制，根据层间 Token 动态自适应分配缓存预算，并配合自适应并行解码阈值校准，以平衡生成质量与效率 [17](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-26&paperId=2606.26120)。

- **创新类型：** 方法设计创新 + 约束处理创新
- **创新性判断：** 现有方法 [1](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-26&paperId=2606.27161) 仅关注视觉 Token 剪枝，[16](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-26&paperId=2606.26769) 仅关注扩散模型的宏轨迹外推，[17](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-26&paperId=2606.26120) 仅关注 dLLM 的缓存与解码。本文首次将两者纳入统一框架，并利用信息论原理解决剪枝目标定义不清的问题，同时用动态策略解决缓存分配僵化的问题，具有明确的互补性和新颖性。

### 创新点二：基于前向信息熵的 KV Cache 压缩与块并行推测解码的联合优化

大多数现有 KV Cache 压缩方法主要依赖注意力权重来估计 Token 重要性，虽然能有效捕捉上下文相关性，但忽略了与预测不确定性和 Token 信息量相关的互补信息论信号 [28](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-26&paperId=2606.26875)[11](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-26&paperId=2606.26861)[18](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-26&paperId=2606.26650)。少数现有方法开始引入信息论指标或推测解码来提升推理效率，但推测解码在扩散模型等非自回归架构中面临特征错配问题，且现有压缩方法未将 Token 的前向影响（即压缩 Token 对未来上下文的影响）纳入考量 [12](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-26&paperId=2606.26744)[17](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-26&paperId=2606.26120)[28](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-26&paperId=2606.26875)。为此，本文提出一种联合优化框架，在 KV Cache 压缩端引入“前向影响”度量，结合 Token 级预测不确定性与层间表示熵，选择对远距离未来上下文影响更大的 Token 进行保留 [28](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-26&paperId=2606.26875)；在解码端，针对多超连接（MHC）等新型架构，采用预折叠残差状态作为条件信号，并引入轻量级门控残差压缩器替代通用线性压缩器，以解决特征错位问题 [12](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-26&paperId=2606.26744)。

- **创新类型：** 问题建模创新 + 方法设计创新
- **创新性判断：** [28](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-26&paperId=2606.26875) 提出了前向影响的概念但未与推测解码结合，[12](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-26&paperId=2606.26744) 解决了 MHC 架构的推测解码问题但未考虑信息论压缩。本文首次将前向信息熵驱动的压缩与架构对齐的推测解码联合优化，解决了两个独立优化目标之间的冲突。

**该论文两个创新点之间的关系：**

## 论文方向二：LLM 服务系统与异构资源编排

**拟定论文题目：** 面向生产级 LLM 部署的动态资源编排：从异构训练模拟到运行时并行度切换与长上下文调度

**论文核心问题：** 如何在异构硬件、动态负载和长上下文场景下，实现 LLM 训练与推理资源的自适应编排，包括异构训练模拟、MoE 模型运行时并行度切换以及长上下文解码调度。

### 创新点三：异构感知的训练模拟器与运行时并行度无缝切换机制

大多数现有 AI 训练模拟器假设同质化的计算和网络基础设施，无法反映真实世界中由于多模态/MoE 架构、公有云硬件快速迭代以及地理分布式部署带来的异构性 [22](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-26&paperId=2606.26633)[29](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-26&paperId=2606.26607)。少数现有方法开始关注异构环境下的负载均衡和通信优化，但通常将张量并行（TP）和专家并行（EP）视为两种独立的部署方案，生产工作负载在突发请求和长尾拖后腿场景下跨越两者边界时，固定布局会损失性能 [29](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-26&paperId=2606.26607)[22](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-26&paperId=2606.26633)。为此，本文提出一种异构感知的统一框架：在训练模拟端，Xsim 支持非均匀工作负载划分、异构感知的集体通信（自定义环构建和分块划分）以及可复用的异构感知抽象 [22](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-26&paperId=2606.26633)；在推理服务端，Moebius 实现运行时 TP/EP 无缝切换，利用两者计算相同函数、共享字节级相同专家权重和 KV Cache 的特性，在不重启引擎或丢弃正在处理的请求的前提下完成布局切换 [29](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-26&paperId=2606.26607)。

- **创新类型：** 系统框架创新 + 在线反馈机制创新
- **创新性判断：** [22](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-26&paperId=2606.26633) 专注于训练模拟的异构感知，[29](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-26&paperId=2606.26607) 专注于推理服务的运行时切换。本文首次将两者结合，提出从训练模拟到推理部署的端到端异构编排方案，并利用模拟器输出的性能模型指导运行时切换决策。

### 创新点四：页感知的长上下文解码调度与自适应效用驱动的资源编排

大多数现有长上下文 LLM 服务系统受限于 KV Cache 移动而非密集矩阵乘法，且分页注意力系统虽然减少了缓存碎片，但低活跃度的长上下文解码会低效利用 GPU，而混合序列长度则在精确长度启动和粗粒度填充批处理之间产生矛盾 [30](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-26&paperId=2606.26666)[24](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-26&paperId=2606.27005)。少数现有方法引入自适应资源编排或闭环控制策略，但通常缺乏对解码调度粒度的精细控制，且未将公平性、可解释性等人本属性纳入统一的效用函数 [24](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-26&paperId=2606.27005)[30](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-26&paperId=2606.26666)。为此，本文提出一种双层优化框架：在解码调度层，PersistentKV 通过按 KV 头分组映射工作、复用 K/V Tile、支持原生页表以及紧凑工作队列调度（仅执行非空行-KV头-序列-分割任务），解决低活跃度长上下文解码的 GPU 利用率问题 [30](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-26&paperId=2606.26666)；在资源编排层，AURORA-AI 通过 Hamilton-Jacobi-Bellman 反馈控制、Lyapunov 稳定性监控和公平性感知复合效用函数，在人口统计偏差冲击、概念漂移和黑天鹅中断等压力场景下持续最大化全局效用 [24](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-26&paperId=2606.27005)。

- **创新类型：** 性能预测创新 + 优化求解创新
- **创新性判断：** [30](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-26&paperId=2606.26666) 专注于解码调度但未考虑全局资源编排，[24](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-26&paperId=2606.27005) 专注于资源编排但未考虑解码调度粒度。本文首次将页感知解码调度与效用驱动的资源编排结合，形成从微观调度到宏观编排的协同优化。

## 论文方向三：LLM 智能体与代码协作的可靠性与治理

**拟定论文题目：** 面向高风险场景的 LLM 智能体可靠性增强：从代码导航锚定到知识协作信任工作流与机构化治理

**论文核心问题：** 如何在软件工程和高风险决策场景中，提升 LLM 智能体的可复现性、知识时效性和行为可控性，包括代码导航的确定性锚定、知识协作的信任工作流以及自主 AI 系统的机构化治理。

### 创新点五：静态锚定驱动的代码智能体导航与知识时效性维护

大多数现有 LLM 代码智能体通过关键词搜索在代码仓库中导航，但忽略了调用图、继承层次和配置依赖等结构关系，导致导航行为随机且难以跨运行复现 [2](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-26&paperId=2606.26979)[27](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-26&paperId=2606.27045)。少数现有方法引入轻量级静态分析或规范驱动架构来提供确定性锚点，但现有规范驱动方法未能解决上下文爆炸和规范-代码静默漂移两个结构性故障模式，且检索增强生成（RAG）缺乏时间模型，当事实发生变化时无法区分新旧值 [2](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-26&paperId=2606.26979)[10](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-26&paperId=2606.26511)[27](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-26&paperId=2606.27045)。为此，本文提出一种双重保障框架：在代码导航端，通过确定性锚定效应注入轻量级静态结构事实（调用/继承拓扑）作为纯文本注释，约束概率探索空间，使导航行为更规范且可复现 [2](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-26&paperId=2606.26979)；在知识时效性端，MemStrata 采用确定性（主体、关系、对象）超驰规则在双时态账本中淘汰过期值，无需相似度阈值或 LLM 调用，在静态知识和推理任务上与 RAG 持平的同时消除过时事实错误 [10](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-26&paperId=2606.26511)。

- **创新类型：** 特征表示创新 + 泛化迁移创新
- **创新性判断：** [2](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-26&paperId=2606.26979) 专注于代码导航的确定性锚定但未考虑知识时效性，[10](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-26&paperId=2606.26511) 专注于知识时效性但未考虑代码导航。本文首次将两者结合，提出从代码结构理解到知识版本管理的端到端可靠性增强方案。

### 创新点六：基于知识包与机构化认证的跨信任边界智能体协作治理

大多数现有 AI 编码智能体在跨信任边界（开源、企业、供应商、承包商）协作时，代码生成速度快但意图理解、范围协商和长期项目责任治理成本高昂，且缺乏对高风险动作（如临床处方、生产部署）的执行控制 [9](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-26&paperId=2606.26721)[15](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-26&paperId=2606.26298)。少数现有方法提出基于知识的拉取请求（KPR）工作流或机构化认证模型，但 KPR 主要关注代码协作流程，机构化认证主要关注动作执行控制，两者尚未形成统一的治理框架 [9](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-26&paperId=2606.26721)[15](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-26&paperId=2606.26298)。为此，本文提出一种双层治理框架：在协作层，KPR 将外部协作者的本地代码、测试和清理后的智能体交互轨迹视为知识源而非默认合并候选，通过智能体蒸馏为人工确认的知识包，并由项目拥有的内部可信编码智能体在接收方环境中重新生成候选代码，从而分离“知识贡献”与“代码合并”两个决策 [9](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-26&paperId=2606.26721)；在执行层，机构化认证模型要求智能体保留规划和推理的完全自主权，但对指定的高风险动作不授予执行权限，执行需满足由独立权威来源各自认证的前提条件，并通过防篡改日志记录 [15](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-26&paperId=2606.26298)。

- **创新类型：** 系统框架创新 + 在线反馈机制创新
- **创新性判断：** [9](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-26&paperId=2606.26721) 提出了知识协作的工作流但未涉及高风险动作控制，[15](https://FAUST-BENCHOU.github.io/daily-arXiv-ai-enhanced/index.html?date=2026-06-26&paperId=2606.26298) 提出了高风险动作的治理模型但未涉及知识协作流程。本文首次将两者结合，提出从知识贡献到动作执行的端到端治理框架。
