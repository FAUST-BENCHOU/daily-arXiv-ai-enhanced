主题 1
LLM 训练与优化：无调度策略、弹性并行与量化压缩
围绕大语言模型训练效率与推理压缩，涵盖无学习率调度训练（ScheduleFree+）、弹性并行切换（DynaTrain）以及基于平坦度的理论最优量化（BDQ），探索从训练到部署的全链路优化。

AI 系统与工程实践：微服务架构、可观测性与自动化调优

一、三篇论文方向与六个创新点

论文方向一：面向在线推理服务的语义感知缓存与成本最优级联路由

拟定论文题目： 面向在线 LLM 推理服务的语义感知前缀缓存淘汰与校准驱动级联路由方法

论文核心问题： 如何在大规模在线 LLM 推理服务中，通过语义感知的缓存管理和校准驱动的路由策略，同时降低推理延迟和计算成本。

创新点一：语义感知的多队列前缀缓存淘汰策略

大多数现有方法将前缀缓存视为统一存储资源，采用 LRU 等通用淘汰策略，忽略了不同语义类型的 token（如系统提示、用户查询、工具输出、思维链）在复用率上存在高达 756 倍的差异 4。少数现有方法开始关注缓存块的语义差异，但通常仅基于单一优先级指标进行全局排序，难以同时兼顾会话内复用、跨会话复用和长尾复用模式 4。为此，本文提出语义自适应多队列淘汰策略，将 KV 块路由到具有不同优先级度量的任务特定队列中，以同时捕捉多种复用模式并提高缓存命中率 4。

  • 创新类型： 方法设计创新
  • 创新性判断： 该创新点基于文献池中 SAECache 4 的核心思想，将其作为少数现有方法的代表，并进一步强化多队列架构与语义感知的结合，具有明确的创新性。

创新点二：校准驱动的成本最优级联路由策略

大多数现有级联路由方法使用未校准的置信度分数，需要针对每个工作负载手动调整阈值，导致部署成本高且泛化性差 9。少数现有方法引入校准技术或贝叶斯优化，但通常假设路由决策与缓存状态独立，忽略了缓存命中率对路由成本的影响 [9, 12]。为此，本文提出校准优先的级联路由方法，通过等渗回归将 token 级边际不确定性映射为逐查询错误概率，并在成本最小化框架中联合建模缓存命中率与路由决策，以在保证准确率的同时最小化端到端推理成本 9。

  • 创新类型： 问题建模创新 + 方法设计创新
  • 创新性判断： 该创新点基于 UCCI 9 的校准路由思想，并将其扩展为与缓存状态联合优化的框架，解决了现有方法中路由与缓存解耦的问题。

  • 评价指标： 缓存命中率、端到端延迟、推理成本、微 F1 分数
  • 消融实验： 分别移除语义感知缓存和校准路由，评估各自贡献

论文方向二：面向异构硬件的多模型调度与弹性训练

拟定论文题目： 面向异构 GPU 集群的多模型 LLM 调度与弹性并行训练方法

论文核心问题： 如何在异构 GPU 集群上，通过弹性并行切换和感知 GPU 差异的专家映射，同时优化多模型训练效率和 MoE 推理性能。

创新点三：基于虚拟参数空间的弹性并行在线切换

大多数现有分布式训练框架基于静态执行模型，无法在训练过程中动态调整并行策略，难以应对资源波动、RLHF 阶段切换和集群弹性变化 2。少数现有方法支持在线重配置，但通常需要较长的切换时间（秒级），且对模型状态迁移的调度缺乏内存感知和死锁避免机制 2。为此，本文提出基于虚拟参数空间（VPS）抽象的弹性并行切换方法，将任意并行配置统一映射到逻辑坐标空间，并设计内存感知、无死锁的状态路由与迁移调度，以实现亚秒级在线重配置 2。

  • 创新类型： 方法设计创新
  • 创新性判断： 该创新点直接基于 DynaTrain 2 的核心贡献，将其作为本文方法的基础，并进一步强调其在弹性训练场景中的适用性。

创新点四：GPU 变异性感知的 MoE 专家映射方法

大多数现有 MoE 推理系统假设 GPU 同质，将专家均匀分布到各 GPU，忽略了 GPU 性能差异导致的掉队者问题 11。少数现有方法考虑负载均衡，但通常仅基于 token 数量进行均衡，未将 GPU 计算能力差异纳入映射决策，导致高负载专家被分配到慢速 GPU 11。为此，本文提出 GPU 变异性感知的专家映射框架，根据各 GPU 的计算能力和专家负载特征，为非均匀 token 分配提供优化映射，以最小化同步屏障下的最慢 GPU 完成时间 11。

  • 创新类型： 问题建模创新 + 方法设计创新
  • 创新性判断： 该创新点基于 GEM 11 的核心思想，将其作为少数现有方法的代表，并进一步强调其在多模型调度场景中的扩展性。

论文方向三：面向生产环境的 LLM 系统可观测性与自动化调优

拟定论文题目： 面向生产环境的 LLM 推理系统可观测性增强与智能体驱动自动化调优方法

论文核心问题： 如何通过增强的可观测性架构和智能体驱动的自动化调优，解决 LLM 系统在生产环境中的诊断困难与性能优化问题。

创新点五：基于因果链的运维记忆架构与可观测性增强

大多数现有 Kubernetes 事件保留模型采用固定窗口或简单轮转策略，在容器高频崩溃循环中，关键故障证据在检查前即被覆盖，形成“证据视界”问题 18。少数现有方法引入事件持久化或日志聚合，但缺乏对故障因果关系的显式建模，难以从孤立事件中重建完整的故障链 18。为此，本文提出运维记忆架构（OMA），通过三种因果模式（OOMKill 链、配置错误链、挂载传播链）将运维事件编码为因果链，并在证据视界之外持久化存储，以支持事后故障诊断和根因分析 18。

  • 创新类型： 系统框架创新 + 问题建模创新
  • 创新性判断： 该创新点基于 OMA 18 的核心贡献，将其作为本文方法的基础，并进一步强调其在 LLM 推理系统诊断中的适用性。

创新点六：基于 LLM 智能体的数据库自动化调优方法
